# Voice Agent Instance A2 设计

日期：2026-08-13  
状态：待用户复核书面规格

## 目标

在 A1 已有租户实例列表、真实 UUID 选择和配置编辑能力上，补齐“网页新建实例”，并提供只允许本地或测试环境使用的幂等演示数据初始化工具。

## 范围

本阶段包含：

- `POST /api/v1/customer-services`。
- “我的实例”页面的新建入口与表单。
- 创建成功后的列表刷新、实例选择保存和配置页跳转。
- 四条完全合成、脱敏的演示实例初始化数据。
- 初始化工具的环境保护和幂等行为。

本阶段不包含：

- 删除、软删除、停用或恢复实例。
- 修改数据库表结构。
- 通话记录管理、租户管理、回拨或预约。
- 自动提交、推送、部署或写入未知/正式数据库。

## API 设计

### 请求

`POST /api/v1/customer-services`

租户身份继续来自现有 `TenantId` 依赖。请求体允许：

- `display_name`：1–80 字符，单行。
- `organization_name`：1–120 字符，单行。
- `greeting`：1–300 字符，沿用现有身份声明和控制字符校验。
- `platform_prompt`：最多 8000 字符，默认为空。
- `tenant_prompt`：最多 8000 字符，默认为空。
- `voice`：可选；缺省时使用 `VoiceProfile` 安全默认值。
- `response`：可选；缺省时使用 `ResponseProfile` 安全默认值。

客户端不得提交 `id`、`tenant_id`、`version`、时间戳或其他未声明字段。Pydantic 使用 `extra="forbid"` 拒绝越权字段。

### 响应

- 成功：`201 Created`，返回完整 `CustomerServiceInstance`。
- 校验失败：`422 Unprocessable Entity`。
- 持久化冲突：采用明确的 `409 Conflict`，不伪装成功。

服务端生成 UUID，使用请求上下文中的租户 ID，并将初始版本固定为 `1`。创建后通过现有仓储保存，因此内存和 PostgreSQL 实现行为一致。

## 仓储边界

新增明确的 `create(instance)` 仓储方法，不复用带乐观锁语义的更新操作来隐式创建。

- 内存仓储拒绝重复 UUID。
- PostgreSQL 仓储执行 INSERT，并把唯一约束冲突映射为领域冲突。
- 创建结果必须能被现有 `get` 和 `list_for_tenant` 查询，且其他租户不可见。

本阶段不增加新的数据库迁移，因为实例表和所需字段已经存在。

## Web 设计

“我的实例”页面增加“新建实例”按钮，打开页面内对话框或抽屉表单。第一版字段为：

- 实例名称
- 机构名称
- 欢迎语
- 音色
- Platform Prompt
- Tenant Prompt

回复参数和其余音色参数使用安全默认值，创建后可在现有配置页继续调整。这样避免在 A2 复制完整配置编辑器。

提交期间禁用重复提交。失败时保留输入并显示可理解的错误；列表加载失败与空列表保持不同状态。成功后：

1. 将返回实例加入或重新加载列表；
2. 将实例 UUID 写入现有会话选择；
3. 关闭表单；
4. 跳转到带 `instanceId` 查询参数的知识库/配置页面。

## 演示数据初始化

提供独立、可重复运行的初始化入口，生成四条合成实例：

- 通用前台
- 售后回访
- 活动咨询
- 内部热线

约束：

- 不包含真实机构、客户、患者、手机号、邮箱、地址、录音或外部下载链接。
- 使用固定、明确标识为 Demo 的 UUID 或稳定键实现幂等。
- 只有显式声明本地/测试环境时才允许执行；生产标志、未知环境或缺少安全开关时立即拒绝且不写入。
- 目标租户必须显式传入或使用仓库已经定义的 Demo 租户，不能扫描或猜测租户。
- 脚本运行前输出目标环境与将创建/跳过的数量，但不输出凭据或连接串。

是否实际运行初始化工具取决于本地数据库连接核验。若无法证明目标是本地/测试数据库，只交付并测试工具，不执行写入。

## 测试策略

严格按测试驱动开发：每项生产行为先写失败测试并确认因功能缺失而失败，再实现最小代码。

后端测试：

- 创建时生成服务端 UUID、使用当前租户、版本为 1。
- 合法请求返回 201，随后列表和详情可查询。
- 客户端提交 `tenant_id`、`id` 或其他多余字段时返回 422。
- 字段、欢迎语和音色校验沿用领域规则。
- 租户之间不可读取新实例。
- 仓储重复创建冲突行为明确。

前端测试：

- 新建入口可用并提交正确字段。
- 成功后保存 UUID 并跳转。
- 失败时保留输入、展示错误且不跳转。
- 提交中禁止重复请求。
- 列表加载失败不显示为“暂无实例”。

初始化工具测试：

- 缺少本地/测试环境开关时拒绝写入。
- 首次执行创建四条合成数据。
- 重复执行不重复创建。
- 其他租户数据不受影响。

最终执行 API 与 Web 全量测试、Python 静态检查、TypeScript 类型检查、前端生产构建和 `git diff --check`。PostgreSQL 集成测试只有在安全的测试数据库存在时才运行。

## 安全与交付边界

- 不读取或展示真实 `.env`、数据库凭据或连接串。
- 不写入未知或正式数据库。
- 不引入客户隐私或真实业务数据。
- 不删除文件或数据。
- 不自动 commit、push、创建 PR 或部署。

## 验收标准

- 用户能从网页创建实例并立即进入该实例配置页。
- 新实例属于当前租户，服务端生成 UUID，初始版本为 1。
- 刷新后实例仍可从数据库列表查询。
- 错误不会被伪装为空列表或成功状态。
- 演示初始化工具在安全环境中幂等，在未知或生产环境中拒绝执行。
- 所有新增行为有经过 Red–Green 的自动化测试，现有功能无回归。
