# 目录调整建议

更新日期：2026-08-13

## 当前合理结构

- `apps/control-plane`：控制面 API 与 Web。
- `apps/runtime`：实时语音运行时。
- `packages`：可复用平台核心库。
- `integrations`：外部系统适配与示例。
- `deploy`：部署资产。
- `scripts`：本地和迁移辅助脚本。
- `docs`：架构、平台、运维、安全、源文档和迁移记录。

## 待确认调整

1. `deploy/src` 与 `apps` 的重复快照应选择“构建时生成部署包”或“明确版本化快照”之一，不能长期人工双写。
2. `scripts` 中仍引用旧目录名的路径应逐项修正，但涉及脚本行为，需单独业务代码授权。
3. 三个 `*.egg-info` 目录属于生成元数据，建议未来从 Git 跟踪中移除；本轮遵守不删除规则。
4. `archive` 原型继续保持仓库外，除非逐项确认仍有复用价值、来源和许可证。
5. 完整 Vapi Adapter 建议未来使用 `packages/vapi-adapter` 或清晰的 `integrations/vapi` 边界，落地前先写接口设计。

## 归档规则

只有不再被构建、部署、测试或引用的内容才可归档。归档记录必须包含来源、最后有效状态、替代实现和恢复方法；不得用归档代替删除确认。
