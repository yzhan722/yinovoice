# 中国大陆牙科电话 Voice 选型输入（v1）

日期：2026-07-28。范围是 PRD 所定义的 **Voice = TTS 引擎 + 具商业权利的预设 Voice**，面向中国大陆牙科电话客服的 `zh-CN` 标准普通话；不是 STT/LLM 排名，也不是法律意见。本文只引用厂商第一方公开文档。所有“自然度”“首包时延”和电话可懂度均为 `not_run`，不能把功能文档或营销描述当成横向质量结论。

## 与本项目的硬约束

- 电话主路径以 8 kHz 为验收音频；要记录供应商原生 8 kHz/编码，或明确记录下采样/转码。
- 用户新意图打断时，编排层必须立即停止本地播放、丢弃未播放音频并取消/关闭当前 TTS 任务；不能只依赖供应商“完成”事件。
- 仅发布已核实商业条款的**预设**音色。首版不开放任意声纹克隆；每个 Voice 记录供应商、模型、Voice ID、区域、版本、许可、速率与格式。
- 目标是端到端“用户说完至 AI 首音”P50 ≤1.2 s、P95 ≤2 s；本文公开证据级别均为 C（能力/接口存在），不是 PRD 评估矩阵所要求的 A 级实测证据。

## 短名单与暂定推荐

**进入首轮大陆实测的短名单（无排名）：**

1. 腾讯云流式文本 TTS：首测 `602005 专业梓欣` 加一男一女的 8 kHz 可用预设 Voice。理由是公开资料同时覆盖 LLM 文本流、8 kHz、预设聊天/客服音色和可取消 SDK；不代表质量优胜。
2. 阿里云 CosyVoice/Qwen-Audio-TTS 系统 Voice：首测两个非克隆系统 Voice，以 8 kHz PCM/Opus。理由是北京端点、双工 task 事件和原生 8 kHz/Opus 明确；取消 API、具体音色许可及自然度仍待实测/合同。
3. 讯飞在线 TTS：首测已购买的两款普通话预设 `vcn`，采用 8 kHz PCM/Opus/Speex 之一。理由是电话格式覆盖和发音人采购机制明确；打断与区域资料不足。

**火山引擎为并行验证候选，不应因资料缺口被判劣。** 开通后先核对 V3 的预设 Voice ID、8 kHz/编码、`cancel` 语义、并发和许可；通过后纳入同一矩阵。国际三家只保留在 `en-AU/en-US/en-GB` 或国际部署对照，不把其公开能力外推为大陆生产推荐。

没有“最佳 Voice”结论：四家中国候选没有在同一江浙口音普通话、牙科词表、8 kHz 失真、网络路径和版本条件下的可比较官方质量/时延数据。

## 取得密钥后必须执行的同一基准

1. **音色与许可闸门**：每厂至少 2 个预设普通话 Voice；保存 Voice ID、模型快照、控制台截图/合同条款、允许的客服用途、区域、计价、并发与下架通知机制。克隆/设计音色一律排除首版。
2. **首音与流式**：以相同的短完整句、长句、LLM token 流各跑 ≥3 轮，分别记录连接/鉴权、首二进制包、首个可播放样本、完整音频和失败率；覆盖北京/大陆电话边缘实际网络，不能用本机 LAN 代替。
3. **8 kHz 电话质量**：对每个候选请求原生 8 kHz（若可用），另做 24k→8k 的受控转码对照；统一输出 μ-law/A-law/SIP 所需格式，5 名以上盲听者对自然度、姓名、日期、金额、手机号与牙科术语可懂度打分。
4. **打断**：在播放 0.2、1、3 秒时模拟新意图；测 VAD 触发到本地静音、网络取消/关闭、供应商停止回包及残留播放毫秒数。验证新轮次不会播放旧音频。
5. **压力与故障**：10 路稳定、50 路压力；记录限流、重连、句尾缓存、取消后再建任务、区域网络抖动及每成功通话分钟总成本。
6. **区域与合同**：向每个供应商书面取得大陆处理端点、海外访问/处理路径、日志/音频保留、子处理者、DPA/SLA、跨境数据条件和采购账户限制；没有可接受书面证据的路径不得进入生产 Business Profile。

## 证据缺口

- 无厂商公开、同数据集的“标准普通话（含江浙口音）+ 8 kHz + 牙科词表”自然度/MOS、发音准确率或首音 P50/P95；只能实测，不能排名。
- 腾讯、讯飞、火山引擎公开页未充分证明海外端点、雅加达调用、处理地域或跨境数据路径；阿里公开的是北京/新加坡端点，不是雅加达证明。
- 预设音色的客服商用、转售/多租户使用、音色撤回和模型升级漂移，要由正式订单/合同核实；“能在控制台调用”不是完整许可证据。
- 打断的公开 API 语义不均等：腾讯 SDK 明示 `cancel`；阿里 TTS 与讯飞需把本地清空播放队列和断连作为适配器标准，并以毫秒实测验收。
