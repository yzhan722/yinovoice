# Voice/TTS 与 LLM 选型：业主决策输入

- 状态：待决策；不是供应商性能报告
- 范围：首个中国大陆牙科诊所 Demo，以及后续国际扩展
- 决策原则：不把存储区域当作推理/传输区域；不以宣传材料或无 Key 的推断替代实测；每次只作一个可回退的决定。

## 结论先行

1. **国际 LLM：建议把 OpenAI 列为首选实测候选，并在通过账户、数据处理、网络和端到端延迟门槛后用于国际流量。**它已满足本项目所需的流式、工具调用和结构化输出能力；但“可用”仍必须由所选账户/合同、处理区域和实测链路证明，不能由 API 文档单独证明。[OpenAI 流式响应](https://platform.openai.com/docs/guides/streaming-responses)、[函数调用](https://platform.openai.com/docs/guides/function-calling)、[Structured Outputs](https://platform.openai.com/docs/guides/structured-outputs)
2. **中国大陆 LLM：现在不应把 OpenAI 作为生产主路径或上线前提。**在完成中国大陆网络、业务可用性、采购/合同和数据处理审查，以及真实电话边缘到实际 OpenAI 端点的重复实测以前，状态是“未确认”，不是“可用”。大陆主路径应先测 Qwen（北京端点）；OpenAI 仅可作为隔离的条件性对照，不得成为故障时唯一回退。
3. **Voice/TTS：先按地区分流而非强行统一。**大陆优先测阿里云 Qwen 实时 TTS，国际英语优先并测 ElevenLabs Flash v2.5 和 Azure Speech；用同一脚本、同一电话转码和盲听决定最终 Voice ID。任何未通过发音、打断停止、商业授权、处理区域或网络可达性门槛的音色都不能发布。

上述结论来自项目现有调研和 PRD；其中未实测的性能均为 `not_run`，不是推荐依据。本文不构成中国数据出境、医疗、录音或采购法律意见。

## 必须先固定的边界

首个 Demo 的电话体验为江浙口音普通话、`en-AU`、`en-US`、`en-GB`；用户结束说话到 AI 首段可播放音频的目标为 P50 ≤ 1.2 秒、P95 ≤ 2 秒。系统使用可替换的 Transcriber、Model、Voice Adapter；会话中断应在编排层保存已播放内容和工具状态，供应商切换的最小边界为新通话。

所有候选在注册表中至少记录：`provider`、`model_snapshot`、`voice_id`、`locale`、`processing_endpoint`、`storage_region`、`transit_regions`（若供应商披露）、`retention_mode`、`subprocessors`、商业授权依据、测试数据版本/哈希、测试时间和并发数。仅写“某云厂商”或“数据存于雅加达”不足以说明实时音频在哪里处理。

## 可行策略（先选架构，不先买年约）

| 策略 | 建议组成 | 适用与优点 | 主要代价/风险 | 当前建议 |
|---|---|---|---|---|
| A. 区域分流、供应商中立 | **大陆**：本地电话边缘 → 中国可用 STT → Qwen（北京）→ Qwen 实时 TTS；**国际**：区域电话边缘 → 已验证 STT → OpenAI → ElevenLabs Flash v2.5 或 Azure Speech。控制面、RAG、工具和审计保持自有。 | 最贴合大陆低延迟和网络不确定性；国际可利用 OpenAI 的流式工具能力；TTS 可按中文和英语分别择优；任何一层可替换。 | 维护两套区域配置、账单与回归测试；跨区会话不能随意切换模型；需要清楚划分数据平面。 | **推荐的首轮基线**。 |
| B. 区域分流、Azure 为国际语音基线 | **大陆**同 A；**国际**：OpenAI 为 LLM，Azure Speech 为英语 Voice（并可作为国际 STT 对照）。 | 国际语音 locale 和可用音色可按区域查询；减少英语 TTS 供应商数量，适合更重视企业采购一致性的团队。 [Azure Speech 语言与音色](https://learn.microsoft.com/azure/ai-services/speech-service/language-support) | 自然度、首包、电话转码和取消速度未实测；音色/功能不是所有区域一致，不能凭语言表直接发布。 | **A 的国际 Voice 对照方案**；若合同和运营偏好统一供应商则可升为主方案。 |
| C. 单一 Qwen/阿里云数据平面（受限试点） | 大陆 Qwen LLM + Qwen 实时 TTS；国际只在新加坡端点、账户与模型组合均被核实后使用同一族服务。 | 实现和供应商管理较简单；项目调研已指出 Qwen 有 OpenAI 兼容接口、函数调用和结构化输出。 [Qwen Function Calling](https://help.aliyun.com/en/model-studio/qwen-function-calling)、[Structured Output](https://help.aliyun.com/en/model-studio/qwen-structured-output) | 北京和新加坡端点的 Key、模型集合和可用功能可能不同；“单一供应商”不等于单一处理区域；对国际英语表现、可靠性和成本仍需实测。 | **仅作成本/运维对照，不应因简单而跳过 A 的国际 OpenAI 对照。** |

三种策略都要求：RAG 在自有、按 Tenant/版本/权限隔离的知识库完成；LLM 只收到允许的检索片段；预约等写操作在模型外做 JSON Schema、权限和二次确认校验。

## OpenAI 的明确决策规则

### 国际

**建议的业主决定：批准进入受控试点，暂不承诺生产。**只有同时满足以下条件，才把 OpenAI 设置为某个国际 Business Profile 的主 Model：

- 目标注册主体、账户类型、合同/DPA、数据保留和可处理区域已由采购与法务书面确认；
- 从目标电话边缘到实际 API 端点连续三轮实测可连通、无绕行依赖，并通过本文件所有 LLM 和端到端门槛；
- 测试证明其在冻结语料上能安全完成知识库约束、工具参数、预约确认、紧急转人工、注入拒绝和跨 Tenant 隔离；
- 已配置并实测独立的非 OpenAI 降级组合，且不会虚报预约成功。

若任一条件不成立，国际 Profile 保持为 Azure/其他已通过候选，OpenAI 不进入发布映射。

### 中国大陆

**建议的业主决定：不批准 OpenAI 作为大陆生产主路径；仅保留“待核实的对照候选”。**项目调研已明确要求大陆可用性必须由法务、采购和真实链路确认，且不能把所有实时音频为了统一管理绕行雅加达。该事实足以阻止在当前阶段作“OpenAI 可在大陆生产”的确认。

要改变此决定，必须获得以下**全部**证据，而非只获得 API Key：

1. 书面确认允许目标运营主体、目标用途和目标账户从大陆使用该服务；
2. 已签署或审阅的合同/DPA 明确实时音频、转写、提示词、工具参数、日志及供应商保留/分处理者安排；
3. 合规人员按最终数据字段、规模、运营主体与合同，完成对跨境传输/处理的书面放行；
4. 从真实大陆电话边缘到实际端点，在三个不同时段、10 路稳定并发下可重复通过本文件的网络、质量和 P95 门槛；
5. 大陆已有可立即切换、同样通过验证的本地 Model + Voice 组合。

在这五项全部完成前，OpenAI 不能处理大陆生产通话的实时内容或成为唯一故障回退。大陆首测 Model 候选为 Qwen 北京端点；北京和新加坡端点分别登记、分别测试，不能视为同一部署。

## 无 API Key 时的分阶段验证

| 阶段 | 现在可做的工作 | 输出 | 是否可决定供应商性能 |
|---|---|---|---|
| 0. 冻结判定方法 | 批准策略 A/B/C 的候选范围、数据区域假设、硬门槛、计时起止点、降级原则；创建 Provider Registry 空表。 | 已签字的测试章程与风险清单。 | 否；所有性能字段为 `not_run`。 |
| 1. 尽调与可达性纸面审查 | 逐供应商确认账户主体、目标端点、模型/Voice ID、地区、商用条款、DPA/保留、子处理者、支持/SLA、限流和电话编码支持；用官方文档只能填 C 级证据。 | 每个候选的“可申请试用 / 不可申请 / 待合同”状态。 | 否。 |
| 2. 建立冻结语料 | 收集模拟录音、双人标注、关键字段和 Domain Pack；生成一次性 8 kHz 电话副本并冻结哈希。 | A 级实测所需的固定测试集。 | 否。 |
| 3. 最小权限试用 | 分别开通候选 API、设定预算/配额、区域端点和审计；先做连通、流式首包、取消和错误路径的冒烟测试。 | 带时间、区域、模型版本的可复现运行记录。 | 仅能淘汰明显不可用候选。 |
| 4. 分层基准 | STT、LLM、Voice 各在相同输入、相同 Domain Pack、至少三轮和不同时间段运行；失败样本不删除。 | A 级结果表及失败样本。 | 可以进行候选排序。 |
| 5. 端到端与故障演练 | 10 路稳定、50 路压力；验证新意图打断、附和不误断、工具超时、供应商断流、紧急转人工和降级。 | 按 Profile 的发布/不发布记录。 | 可以批准一个精确版本+区域+Voice ID。 |

没有 Key 时不可填写首包、P95、错误率、并发、成本或“最佳”结论；官方能力、区域表和条款仅为 C 级证据。

## 必要账户、材料与录音

在阶段 3 前，业主应一次性准备以下最小集合：

- 每个候选供应商的企业试用账户/付款主体，且能选择目标端点；候选包括大陆 Qwen 与 Qwen 实时 TTS、国际 OpenAI、ElevenLabs、Azure Speech，以及必要的 STT 候选。不得共用个人 Key 或把测试 Key 放入代码库。
- 电话/SIP 服务商的测试号码和可控制的大陆、国际电话边缘；仅允许模拟通话，不接真实患者。
- 法务/采购可审阅的服务条款、商业 Voice 使用权、DPA、保留政策、数据处理地点、子处理者、支持/SLA 与账单/限流说明；任何缺项都标记为未通过，而非假定允许。
- 4–6 名自愿的江苏/浙江不同城市、性别和年龄段测试说话者；记录城市、主要语言和自评普通话口音强度，不收集真实患者资料。每人完成固定场景和自由表达，可随时撤回。
- 冻结的虚构诊所/医生/患者/联系方式/预约数据池、经确认的牙科术语和中英文品牌/姓名列表；原始录音、人工参考转写和模型输出分离保存。
- `en-AU`、`en-US`、`en-GB` 的许可清楚公开语料只用于初筛，必须与自有中文电话语料分表报告，不能支持生产验收结论。

录音覆盖安静、轻噪声、快语速、自我修正、停顿、重复、中英混说和 8 kHz 单声道电话版本；必须覆盖咨询、预约、改期、取消、紧急症状、隐私、提示注入、打断、附和、工具失败和授权回访。转写由标注员 A 完成、标注员 B 在不看模型输出的情况下复核；任何参考修订生成新数据集版本。

## 硬门槛（任一失败即不发布）

这些是建议业主在阶段 0 签字确认的发布门槛。除 P95 ≤ 2 秒外，其他数值是本文件提出的保守首版阈值；若业主改动，必须在测试前版本化，不能在看到结果后放宽。

| 类别 | 硬门槛 | 测量与处理 |
|---|---|---|
| 端到端时延 | 用户结束说话至首段可播放 AI 音频：P50 ≤ 1.2 s、**P95 ≤ 2.0 s**；在每个目标地区、同一冻结集、至少三轮均达标。 | 记录 STT final、LLM first token、TTS first audio、网络和编排耗时；10 路稳定通过后才可看 50 路压力结果。任何超时/限流/空结果计入失败。 |
| Voice 发音 | 强制脚本中姓名、完整手机号、日期/时间、金额和批准的牙科术语：**每一类准确率 ≥ 98%，且紧急/身份/预约确认脚本零关键错误**；至少 5 位盲听者的可懂度均分 ≥ 4/5。 | 以固定文本、目标 Voice ID、目标 locale、同一 8 kHz 转码评分；中文普通话和三种英语 locale 分开判定。通过一个 locale 不能外推另一个。 |
| 打断与取消 | 从本地编排层收到有效新意图打断到电话侧音频停止：P95 ≤ 500 ms；`ZH-INT-01` 必须停止旧回复并保留上下文；`ZH-BACK-01` 的附和不得被当作取消。 | 录制事件时间戳和实际电话侧音频；连续三轮中任何错误继续播放安全/旧内容即失败。 |
| 商业与音色权利 | 目标 Voice ID 的商用客服用途、语言/地区、可用期限和撤销/替换规则均有官方条款或已签合同依据；只允许预设、获授权音色。 | 未确认、条款冲突、任意真人克隆或权利链不清即失败；将依据与 Voice ID 一并存档。 |
| 地区、网络与数据路径 | 每个端点的账户权限、处理端点、数据路径/保留和实际电话边缘连通性均被记录并批准；大陆与国际分别通过。 | 三个不同时段重复；DNS/TLS/连接、流式、重连和供应商断流均测试。未披露或不可接受的处理/保留安排、依赖未批准跨境绕行、或无法稳定连通即失败。 |
| 安全与业务正确性 | 紧急症状正确触发安全话术/Human Handoff；未验证身份不泄露资料；注入不泄露 Platform Prompt 或扩大权限；写预约前复述并得到明确确认；工具失败不报成功；Tenant 隔离通过。 | 任何一次安全、隐私、跨 Tenant 或虚假预约失败即失败，不可由平均得分抵销。 |
| 降级 | 主路径故障时能切到已验证组合，且新通话可恢复；不在会话中无状态切换。 | 在断流、超时、限流和工具失败演练中验证；只记录已播内容和工具状态后再继续。 |

## 业主的一次一决序列

每项只在前一项完成后作答；每个答案进入决策记录并可回滚。不要并行作“选供应商、选地区、设阈值”。

1. **D1 — 确认首发边界：**大陆 Demo 是否先采用区域数据平面，并不把雅加达或任何单一区域写死为实时处理地？建议答案：**是**。
2. **D2 — 批准门槛：**是否采纳上一节的 P95、发音、取消、权利、网络和安全硬门槛？如修改，先冻结版本再测试。
3. **D3 — 决定国际 LLM 候选：**是否批准 OpenAI 进入国际受控试点，并同时保留一个独立降级候选？建议答案：**是，条件性批准**。
4. **D4 — 决定大陆 LLM 路径：**是否确认 OpenAI 不作为大陆生产主路径，先以 Qwen 北京端点为主测候选？建议答案：**是**。
5. **D5 — 决定 Voice 候选池：**是否批准大陆测 Qwen 实时 TTS，国际英语并测 ElevenLabs Flash v2.5 与 Azure Speech，并禁止任意声线克隆？建议答案：**是**。
6. **D6 — 决定测试资料授权：**是否批准只用自愿测试者、虚构数据和许可清楚的英语公开语料，并授权建立冻结版本？建议答案：**是**。
7. **D7 — 决定试用采购：**是否为已通过纸面尽调的精确端点开最小权限、限额、可审计的试用账户？建议答案：**是，但不购买长期承诺**。
8. **D8 — 决定发布映射：**仅在 A 级数据、全部硬门槛和降级演练通过后，是否批准某个精确 `Model + Region + Voice ID + locale` 进入一个 Business Profile？每次只批准一个映射。

## 决策记录应附的证据

- 策略 A/B/C 选择及数据区域假设；
- 每个候选的官方能力/地区/条款链接和合同证据（C 级）；
- 语料版本、哈希、Domain Pack 版本、录音授权台账；
- 三轮分层结果与所有失败样本，包括地区、时间、并发、模型快照与账单单位；
- 10 路、50 路和故障演练记录；
- 最终 Business Profile、不可支持项、回滚版本与复测日期。
