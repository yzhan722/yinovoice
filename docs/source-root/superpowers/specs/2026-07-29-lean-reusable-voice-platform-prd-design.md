# 精简可复用语音客服 PRD 设计

## 背景

原 PRD 以中国大陆牙科诊所为主要产品边界，并包含外呼、回访、强制 AI/录音披露、复杂数据治理和生产级压力测试。团队确认当前产物只是内部、评委或受邀测试者使用的 Demo；长期产品应是可复用的 AI 语音客服平台，牙科只是一个示例分支。

## 已选择的文档方案

团队选择直接精简现有单一 PRD，不拆分平台 PRD 和牙科 Demo Spec。新版在同一文档中先定义通用平台能力，再用牙科流程展示配置如何落地。

## 设计决定

- 产品核心由电话接入、实时编排、Transcriber、Model、Voice、Prompt、知识库、Tool Adapter、打断和日志组成。
- 行业复用依靠替换 Tenant Prompt、Knowledge Base、Tool Set、Voice 和少量 Fallback Rules，不复制编排层。
- 当前 Demo 仅支持入站咨询、预约/改期/取消、转人工和失败回拨任务，不实现自动拨号、主动外呼或回访。
- Demo 为内部受控演示，开场不强制声明 AI 身份或录音；生产化章节明确该简化不得直接沿用到真实患者。
- 工具失败时不虚报成功、不自动重复可能造成双写的动作，而是创建回拨任务、通知人工并把任务 ID 写入 Call Record。
- 医疗限制压缩为两个基础规则：AI 不诊断；明显紧急描述进入人工或急救提示。
- Demo 保留 10 路并发和 P95 两秒目标，移除 50 路压力、复杂跨境、完整计费、生产 SLA 和声音克隆验收。
- 验收聚焦基础流程、知识库正确性、工具确认、失败回退、打断、模型可替换和基础日志。

## 被否决的方案

- 继续保留牙科专用 PRD：修改最少，但不能清楚表达平台复用目标。
- 拆分通用平台 PRD 与牙科 Demo Spec：边界更清晰，但团队当前更偏好单文档和较低维护成本。

## 复用判断

牙科配置能够替换为餐厅等行业的 Prompt、知识库和工具，而不修改 Transcriber、Model、Voice 或 Tool Adapter 的公共接口，即视为满足当前 Demo 的复用目标。
