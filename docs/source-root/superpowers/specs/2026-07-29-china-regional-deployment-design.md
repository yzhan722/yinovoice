# 中国大陆区域部署设计

## 背景

早期讨论曾考虑把数据集中存储在阿里云雅加达。团队现已决定当前阶段不考虑雅加达：面向中国大陆诊所的 Demo 应部署在中国大陆，并优先使用具有大陆处理端点的商业模型。

## 已选择方案

当前只建设一个 China Regional Cell，同时在接口和数据模型中保留区域字段。这样能控制 Demo 范围，也能避免未来新增海外区域时把区域逻辑写死。

## 区域边界

China Regional Cell 包含电话接入、实时编排、后台服务、数据库、对象存储、向量库、缓存、日志、备份以及 Transcriber、Model 和 Voice 的处理端点。

患者测试数据、实时音频、转写、Prompt、知识库、工具参数、预约、回拨任务和日志不离开中国大陆。本阶段没有全球控制平面，也不向雅加达或其他海外区域同步运营数据。

## Provider 准入

Provider Adapter 保持供应商中立，但运行时选择受区域白名单约束。每个配置记录 API 端点、处理区域、存储区域、保留方式、商业状态、模型版本和最近验证日期。

配置只有在大陆端点可调用、处理与保留区域可确认、商业条款可接受、统一基准达标且不会自动回退到境外时，才能标记为 `CN_ALLOWED`。品牌注册地不能替代端点和数据路径验证。

大陆 Tenant 只选择平台发布的 Business Profile 和预设 Voice。Platform Operator 负责把通过准入的底层模型组合映射为中文高质量、低延迟或低成本档位。

## 失败处理

- 配置未通过 `CN_ALLOWED` 时，在发布阶段阻止启用；
- 运行时发现端点或准入状态不匹配时，停止模型请求并记录错误；
- 只允许降级到另一个 `CN_ALLOWED` 配置，不能自动切换到境外 Provider；
- 没有可用大陆配置时，通话进入人工或回拨任务流程。

## 验证要求

- 检查应用、数据库、对象存储、向量库、日志和备份的实际区域；
- 捕获模型请求的目标域名和端点配置；
- 对每个 Provider 核对控制台、合同或书面区域材料；
- 使用同一 8 kHz 电话集验证准确率、首包延迟、P95、打断和故障降级；
- 模拟大陆 Provider 故障，确认系统不会把请求发送到境外。

## 未来扩展

未来进入澳洲或东南亚时新增独立 Regional Cell，并为该区域单独建立 Provider 白名单、数据存储和运营规则。大陆内容数据不默认迁移或复制到海外。
