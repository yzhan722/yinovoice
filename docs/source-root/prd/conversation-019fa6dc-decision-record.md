## 1. 已确认的产品边界

- 首个垂直场景是中国大陆牙科诊所，服务对象是中国大陆患者；后续通过配置扩展到其他行业。
- 首版覆盖三类核心电话任务：入站咨询、预约/改期/取消，以及对已授权且真实就诊患者的回访、提醒和回拨。
- 目标是脱离 Vapi，建设自有实时语音智能体编排层；电话线路继续使用合规的第三方云通信或 SIP 服务。
- 编排层负责 STT、LLM、TTS、VAD/打断、工具调用、日志、计费、模型路由和故障降级。
- Demo 使用商业模型 API，不自行训练 STT/TTS，不在首版自建 LLM GPU 推理集群。
- 本轮交付聚焦“选型阶段包”，不直接实现完整的 Vapi 替代平台。

## 2. 已确认的配置与领域语言

- 用户界面采用三个稳定模块：`Transcriber（STT）`、`Model（LLM）`、`Voice（TTS + 音色）`。
- 普通诊所不任意拼装底层供应商；平台运营方发布经过验证的 Business Profile，诊所选择业务档位与预设音色。
- Provider Adapter 保持供应商中立；当前大陆 Demo 只允许通过大陆区域准入的供应商配置，国际厂商留待未来海外 Regional Cell 评估。
- STT/TTS 首版是平台内部可替换能力，不单独作为公开 API 产品出售。
- 术语定义以仓库根目录的 [CONTEXT.md](../../CONTEXT.md) 为准。

## 3. 已确认的语言与数据集范围

- Demo 覆盖江浙口音普通话输入，以及 ENG-AU、ENG-US、ENG-GB；普通话输出使用标准普通话，英语输出按诊所配置选择对应地区音色。
- 每个 Voice Agent 有主要语言；开场检测语言，置信度不足时确认，并允许通话中中英切换。
- 江浙口音普通话使用团队自行模拟电话建立测试集：至少 4–6 名来自江苏或浙江不同城市的说话者，固定场景与自由表达结合。
- 每条录音由一人转写、另一人复核；姓名、电话、日期、时间和牙科术语另行标注，参考答案在测试前冻结。
- 英语三种口音可先使用许可证清晰的公开数据做初评；公开数据结论不能等同于生产验收。
- 当前没有商业模型 API Key，因此厂商能力只能先做官方资料初筛；真实准确率、延迟和成本必须标为 `not_run`，不能伪造实测排名。

## 4. 已确认的模型评估方法

- Transcriber 使用中文 CER、英文 WER、关键字段准确率、8 kHz 电话音质、噪声、中英混说、首个部分结果/最终结果延迟、稳定性、失败率和成本。
- Model 使用牙科客服统一场景，评价知识库忠实度、字段提取、工具调用、安全转接、提示注入防护、中英切换、首 token 延迟、完整响应时间和成本。
- Voice 使用统一中英文脚本，评价首段音频延迟、人名/数字/日期/金额/牙科术语发音、地区音色自然度、长句稳定性、取消播放速度、商业授权、并发限制和成本。
- 关键字段错误不能被较低的整体 CER/WER 掩盖；安全、跨租户隔离和虚假预约属于硬门槛。
- 不得把不同数据集、音频格式、地区或测试条件下的厂商宣传数字直接排列为“最佳模型”。

## 5. 已确认的 Prompt、知识与安全边界

- Platform Policy 用代码强制执行医疗安全、外呼授权、身份披露、数据访问和工具权限。
- Platform Prompt 由平台运营方控制且对租户不可见；Tenant Prompt 只控制品牌、语气和业务流程，不能扩大权限。
- 每家诊所维护独立、可审核、可发布和可回滚的 Tenant Knowledge Base。
- 一次知识发布同时生成 Domain Pack：事实进入 LLM 检索，诊所名、医生名和专业术语进入 STT 热词或 contextual biasing。
- AI 只提供诊所批准的一般科普与行政信息，不进行诊断或个性化治疗决策。
- 高风险症状触发固定安全话术；有坐席时转人工，无人接听时创建高优先级回拨，疑似危及生命时提示联系当地急救服务。
- 外呼只允许诊所已授权且确实就诊的患者；禁止冷呼和外购营销名单。
- AI 身份与录音披露属于平台强制步骤，诊所只能定制文案，不能关闭流程。

## 6. 已确认的通话、预约与打断规则

- 诊所现有预约/诊所管理系统是 Scheduling Authority；平台通过 Scheduling Adapter 查询和写入。无外部系统的小诊所才使用平台内置日历。
- 预约、改期或取消前必须复述关键字段并取得明确确认；工具失败时不得声称操作成功。
- 默认允许患者打断 AI；附和词不应误触发中断，新意图需要取消未播放内容并保留会话状态。
- 来电号码只能匹配候选患者；身份验证前不得泄露敏感历史，敏感操作可增加验证码或人工核验。

## 7. 已确认的非功能目标

- Demo 功能验收支持 10 路稳定并发，压力测试覆盖 50 路并发。
- 用户说完到 AI 开始出声：P50 不超过 1.2 秒，P95 不超过 2 秒。
- 分阶段记录 STT final、LLM first token、TTS first audio、网络和工具调用耗时。
- 默认保存 Call Record，并对录音、转写、摘要、工具结果和审计日志设置不同保留期与可审计删除流程。

## 8. 2026-07-29 大陆部署决定

- 当前 Demo 只建设一个 China Regional Cell，不建设雅加达或全球控制平面。
- 应用、数据库、对象存储、向量库、缓存、日志和备份全部位于中国大陆。
- 患者测试数据、实时音频、转写、Prompt、知识库、预约和工具数据不跨境传输。
- Transcriber、Model 和 Voice 优先选用大陆商业服务，并且必须具有经验证的大陆处理端点。
- Provider Registry 使用 `CN_ALLOWED` 控制运行时准入；国产品牌本身不能证明数据处理区域符合要求。
- 普通 Tenant 仍只选择业务档位和预设 Voice，底层大陆模型组合由 Platform Operator 发布。
- 后续国际化通过新增彼此隔离的 Regional Cell 实现，不默认复制大陆内容数据。

## 9. 2026-07-29 通用 Demo 与模板决定

- 第一交付物是行业无关且可独立验收的 Platform Core 和 Generic Receptionist Template。
- 通用接待员模板独立支持 FAQ、信息收集、通用预约、打断、转人工、回拨和日志。
- Dental Template 必须由已发布的通用模板派生，牙科不是 Platform Core 的默认业务流程。
- 牙科专用化只修改 Prompt、知识结构、工具字段、Domain Terms、Voice 和安全规则，不修改或复制实时编排代码。
- Tenant 从已发布的 Domain Template 创建 Voice Agent Instance；实例固定绑定 Template Version。
- 已发布模板版本不可原地修改；升级由 Tenant 明确触发，不能覆盖 Tenant 自有知识和允许覆盖字段。
- 模板缺少必填字段、工具 Schema、回退规则或评估结果时不能发布。
- Gate A 先验收通用 Demo，Gate B 再验收牙科模板和至少两个相互隔离的诊所实例。

## 10. 仍未收敛、不得写成既定事实的事项

- 首轮实际开通的 STT、LLM、Voice 供应商、账户区域与测试预算。
- 各候选供应商的大陆处理区域、服务端保留方式、合同条款和故障转移路径。
- 中国大陆电话/SIP 供应商、号码合规方案，以及各地区适用的披露与录音同意文本。
- 身份验证强度、首批诊所系统连接器优先级，以及完成统一基准后各 Business Profile 的模型映射和发布门槛。
